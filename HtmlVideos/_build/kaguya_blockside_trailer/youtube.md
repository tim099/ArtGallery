## 上架前要確認（給 Tim）

- 遊戲網址要不要放：描述裡用的是片尾按鈕的同一個網址（`TR_LATEST`）。
- 「製作：Tim」那行的署名寫法。
- 縮圖：畫廊的縮圖是 455.2 秒那格（片名）。YouTube 縮圖建議要更吵一點，例如 5.5 秒（開場兩艘對轟、木屑飛出去）、163.6 秒（三叉戟號的帆被鏈彈撕成一條條）、219.6 秒（光榮號傾側、砲門闔上）、54.4 秒（弩砲的弦剛彈出去、火箭離弦）、306.4 秒（收穫號衝上珊瑚礁、礁上翻白浪）或 431.5 秒（從漩渦眼往上看，風暴角號在水牆頂上開砲）。
- 片子怎麼錄成影片檔：**不要用螢幕錄影**（會掉格、載船時會停）—— 用 `record.sh` 逐格錄（Tim 2026-10-19：「確保錄製不掉fps的影片」「可以加個.sh直接執行嗎」）：

  ```bash
  ./record.sh
  ```

  - `_build/kaguya_blockside_trailer/record.sh`，在哪個資料夾跑都可以（它是 `python -I record.py` 的捷徑，參數照傳）。它會開一個 Chrome 視窗、一格一格算到每一個 1/60 秒、畫好交給瀏覽器編碼；一格算多久都沒關係，成品是準確的 60 fps、一格不掉。聲音照同一條時間軸另外錄（不跑模擬、1 倍速重播），砲聲跟畫面對齊。
  - 寫到「影片」資料夾的 `kaguya_blockside_trailer_60fps.webm`（1080p、VP9 約 22 Mbps ＋ Opus 256 kbps，整支約 1.2 GB；YouTube 收 WebM）。
  - 先試一小段：`./record.sh --from 125 --to 135`；30 fps：`--fps 30`；全部參數：`--help`。錄的時候那個 Chrome 視窗別最小化。
  - 錄影程式（record.js）只在錄影當下注入一份複製，畫廊那一份不帶它。
  - 片尾那兩顆按鈕是網頁元素、錄不進去 ⇒ 錄影時畫一張片尾字卡（「在瀏覽器裡直接玩」＋網址）。
